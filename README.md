# steering_agents

Re-implementation of the experiments of *Homogenization in Multi-Agent Systems* (Ganesh et al., arXiv:2610.09824) with a
single open model (Qwen3.8-27B served by vLLM). An orchestrator-driven multi-agent system (workers with different personas
score the same item for T=5 rounds, an orchestrator aggregates and broadcasts the shared state) is run on three applications:

| app | workers | orchestrator | data |
|---|---|---|---|
| `coding` | security / optimality / correctness / readability reviewers | code generator | CodeLMSec stubs + CodeQL |
| `hiring` | subject-matter / experience / impact / operational evaluators (one can be adversarial) | none | synthetic counterfactual resumes |
| `review` | pragmatist / theorist / empiricist reviewers | meta-reviewer + author | ICLR 2025 papers |

Metrics: conformity (variance across agents), polarization (distance of the panel mean to the scale endpoints) and inertia
(change of the panel mean between rounds), plus CodeQL vulnerability rates, hiring bias and per-area review scores.
See `report/main.tex` (Overleaf-ready, with the first results) and `notes/plan.md` (design decisions and deviations).

## Layout
- `steering_agents/` library: `llm.py` (vLLM engine), `mas.py` (resumable batched runner), `metrics.py`, `apps/{coding,hiring,review}.py`
- `scripts/` launcher (`launch_mas_pipeline.py`), worker (`run_mas.py`), data prep, `analyze.py`, `quality_report.py`, `codeql_eval.py`, `estimate_cost.py`
- `data/personas.json` persona prompts from the paper's Appendix I (built by `scripts/extract_personas.py`), `data/hiring/bls_directions.json`
- `tests/fake_engine_test.py` CPU-only end-to-end test with a fake engine

## Setup
1. Python env with `vllm`, `torch`, `transformers`, `numpy`, `pandas`, `matplotlib` (tested: vllm 0.25.1), plus `pymupdf`, `remotezip`, `openpyxl` for data prep.
2. Download `Qwen/Qwen3.8-27B` into your Hugging Face cache (`HF_HOME`). Compute nodes may be offline, so download beforehand.
3. Data. Included in `data/` (everything needed to rerun without downloading datasets):
   - `personas.json`: persona prompts from the paper's Appendix I (rebuild with `scripts/extract_personas.py` from the paper PDF)
   - `codelmsec/benchmark/`: the 280 CodeLMSec code stubs (200 Python, 80 C), released with https://github.com/codelmsec/codelmsec
     (Hajipour et al., SaTML 2024)
   - `hiring/pairs.jsonl`: the 195 job description / resume pairs used in our run (generated by the model with the paper's prompts;
     demographic signals are inserted at run time from `steering_agents/apps/hiring_data.py`); regenerate with `scripts/build_hiring_data.py`
   - `hiring/cpsaat11.xlsx` (BLS CPS Table 11, public domain) and `hiring/bls_directions.json` (derived, via `scripts/prepare_bls.py`)
   - `iclr2025/paper_manifest.csv`: ids, decisions and areas of the 1,918 ICLR 2025 papers we used
   Not included (download once; the scripts do it):
   - ICLR paper texts (third-party): `python scripts/prepare_iclr_data.py` rebuilds exactly the manifest's set from the public
     mirrors `demfier/reviewertoo-iclr2025` (metadata) and `simon123905/iclr2025_all_zips` (PDFs); needs `pymupdf`, `remotezip`
   - CodeQL CLI bundle (https://github.com/github/codeql-action/releases) unpacked to `tools/codeql_bundle/` for the coding analysis
   - Model weights: `Qwen/Qwen3.8-27B`
   Results of our run: `results/medium_20261026/` (metrics `summary.json`, `quality_report.md`) and `report/`.
4. Cluster settings are read from the environment by the launcher: `STEERING_ENV_SETUP` (modules / conda activate),
   `STEERING_TMP`, `HF_HOME`, `SLURM_GPU_PARTITION`, `SLURM_CPU_PARTITION`, `MAIL_USER` (optional).

## Run
```
python tests/fake_engine_test.py                                  # CPU check
python scripts/launch_mas_pipeline.py --tier medium --dry-run     # writes the sbatch files only
python scripts/launch_mas_pipeline.py --tier medium               # one GPU job per application
python scripts/launch_mas_pipeline.py --resume experiments/<run>  # continue an interrupted run (saved replies are reused)
python scripts/analyze.py --run-dir experiments/<run>             # figures + summary.json; also run by each job at its end
python scripts/estimate_cost.py                                   # rough GPU-hour estimate per tier
```
Every reply is appended to `experiments/<run>/<app>/records_shard*.jsonl` as soon as it finishes.
