# Plan: reproduce "Homogenization in Multi-Agent Systems" (arXiv 2610.09824) with Qwen3.8-27B (bnb 4-bit, in-flight)

Paper text: `notes/paper_text_pypdf.txt` (pypdf extraction). Personas/prompts (Appendix I): `data/personas.json`
(built by `scripts/extract_personas.py`; do not hand-edit).

## What is reproduced
Orchestrator-driven MAS (Alg. 1): T=5 rounds; workers output (score r_i, metadata c_i); orchestrator O aggregates and
broadcasts global state. Metrics per (item, trial), averaged over dataset: conformity (variance of agent scores falls),
polarization (mean score distance to nearest scale endpoint falls), inertia (|mean change| falls over rounds).

| app | workers | orchestrator | score | data |
|---|---|---|---|---|
| code | 4 reviewers (security, optimality, correctness, readability) | code generator (writes g1, rewrites after feedback) | deployability 1-5 | CodeLMSec 280 stubs (200 py, 80 c) |
| hiring | 4 evaluators (subject matter, experience, impact, operational) | none: concatenation of (score, reasoning) | fit 1-5 | 200 JD-resume pairs x 40 demographic variants |
| review | 3 reviewers (pragmatist, theorist, empiricist) | meta-reviewer summary + author rebuttal | rating 1-10 | ICLR 2025 papers (main text) |

Downstream analyses: CodeQL vulnerability rates (all code, and "deployed" = panel mean >= 3), hiring bias
(most-minus-least privileged group, adversary in 2 rounds then removed), peer-review per-area mean spread, trial variance
(sampling stochasticity), LLM-judge code similarity across the 10 trials.

## Deviations (forced by cluster / "only Qwen3.8-27B for now")
- One model for every agent (paper's single-LLM setting). The 16 mixed-model setups are not run (config supports a
  per-role model name, but only one engine is loaded per process).
- Model: `Qwen/Qwen3.8-27B` (bf16) quantized to bnb 4-bit by vLLM at load (`quantization=load_format=bitsandbytes`,
  `gdn_prefill_backend=triton` for the gated-delta-net layers); `reasoning_effort=medium` (template default xhigh is too long).
- Peer review: OpenReview is behind a challenge page from here. Metadata (decision, primary area, arXiv id) from
  `demfier/reviewertoo-iclr2025` (iclr2025_full), PDFs from `simon123905/iclr2025_all_zips` (read remotely), all text via
  PyMuPDF (`scripts/prepare_iclr_data.py`). Sample = all Oral+Spotlight (592) + 300 Posters + 999 Rejected + 27 desk-rejected
  (arXiv versions) = 1918 papers (`data/iclr2025/papers_review.jsonl`). Withdrawn papers (and most desk rejects) have no
  text anywhere reachable, so the paper's 'rejected+withdrawn' slot is filled with rejected only.
- Hiring stereotype directions now come from the real BLS CPS Table 11 (`data/hiring/cpsaat11.xlsx` ->
  `scripts/prepare_bls.py` -> `data/hiring/bls_directions.json`, loaded by `hiring_data.py`); ethnicity order = over-representation
  vs all occupations (paper unspecified; `--raw-share` for raw shares).
- Hiring data: JDs/resumes are generated by Qwen3.8 itself (paper: Gemini 3.1 Pro); resume prompt is the paper's.
  Demographic signals (5 variants x 8 groups) are authored here following Table 3.
- Code similarity judge = the same model (paper: cross judges).
- CodeQL 2.27.3 bundle in `tools/codeql_bundle` (python-security-extended, cpp-security-extended).
- Full scale is huge (hiring alone: 8000 x 10 trials x 5 rounds x 4 agents = 1.6M calls). Every stage takes
  `--n-items --n-trials`; the default tier is a pilot. Scale up from measured throughput.

## Layout
`steering_agents/{llm,jsonio,mas,metrics}.py` core; `steering_agents/apps/{coding,hiring,review}.py` per application;
`scripts/run_mas.py` worker (resumable, `--shard i/n`); `scripts/launch_mas_pipeline.py` sbatch chain;
`scripts/analyze.py` figures/tables.
